# 复分补充层维护说明

## 数据边界

基础类目由 `chinese-library-classification==0.0.1` 与项目内的第五版官网覆盖数据共同组成。`clc_rules/base.py` 读取原包JSON一次，再合并 `clc5_base_overlay.json`；不改 `.venv/site-packages`。官网抓取标记为不完整，因此只覆盖可唯一确认的主表节点，未出现的深层类目仍由原依赖兜底。生成边界与复现方法见[第五版基础类目数据维护](clc-base-data.md)。`tables.json` 只处理复分表局部编号，不能与基础主表混为一套全局分类号。

本机PDF只用于提取规则证据。运行网站不需要PDF、OCR软件、网络分类服务或语言模型。

当前是第一阶段可用实现，不是全书规则引擎验收完成。最新范围见[覆盖报告](clc-rule-coverage.md)。

## 解析顺序

1. 保存原始输入；仅对副本做全角、空白、大小写和标记规范化。
2. 合并后的基础类目精确命中时保留其类名及父链。已核对的历史例外只增加注释，不改原号。
3. 未精确命中时，尝试已审核的范围/仿分/专用表规则。取能够确认的最长部分，不能被原来的一级大类截断抢先结束。
4. 对已经确认的主类或复分结果继续解析显式标记；带符号的主表专类优先。
5. 遇到未识别部分即停下，后续的时代、地区等不越过未知片段继续推测。
6. 返回路径、状态、未解析部分和来源。没有消耗完号码时，不得标成规则补全。

基础适配沿用依赖或官网节点明确提供的 `up_level`，不会用逐位截短推测父子关系。小数点用于显示分组，不是语义层级；复分规则对已知构造副本去点，并把消费长度映射回规范串，从而保留尾缀中的小数点和标记。

## 当前执行类型

| 类型 | 用途 |
|---|---|
| `append_table` | 明确作用域后直接接时代、地区、民族或题材表；支持排除子类 |
| `imitate` | 保留本类父链，移植已确认目标类的相对细目 |
| `zero_table_imitation` | 范围类的一般性问题仿分，例如S51/59先接0再仿S50 |
| `foreign_literature` | 世界地区与I3/7专用表，只有明示仿09的类型才接时代 |
| `country_biography` / `world_biography` | 仿K82的相对学科细目，不带入中国父类及时代/民族表 |
| `general` / `marked_region` / `marked_time` / `marked_ethnic` / `environment` | 显式区分符号的通用复分 |
| `annotation` | 有证据的停用或主表专类优先注释 |

表号不能混用：世界地区382是以色列，而世界民族382是犹太人；国际时代43是1870—1917年，中国时代43是五代、十国。国家上下文只取自明确主类或已解析的地区，不从ISBN、作者、书名猜测。

`-` 与 `<>` 均不能在同一号码中重复使用本表的多个特征；未知冒号组配、未核对的数字尾缀、缺少闭合标记都保留为未解析。未知表号不会自动按最长数字补出一个貌似完整的地点或民族。

世界地区表198.1/.8有历史属性适用限制，但地区号的已知含义与本书是否符合该限制是两回事。对于已确认主类后完整、已知的地区号，解释其含义并标记`historical`，同时提示编目适用性尚未鉴定。例如`I12(198.4)`补出“古代希腊”；`O4(198.5)`也只能说明原号中的地区指“古代罗马”，不据此认定该号适合这本书。不得以类名包含“历史”或以“史”结尾作为合规判断。未录入表项、未知尾缀和缺少闭合括号仍返回部分解析。

## 返回状态

| `status` | 含义 |
|---|---|
| `exact` | 合并后的基础类目精确匹配；不表示已经按PDF重新鉴定编目有效性 |
| `supplemented` | 已审核规则解释了当前号码的全部字符 |
| `partial` | 只解释了前一部分，`unparsed` 明确给出剩余内容 |
| `empty` / `unknown` / `invalid` | 空值、无可确认类目、明显格式异常 |
| `unavailable` | 基础类目等本地解析数据不可用；不算国图失败 |

`complete` 是消费号码是否完整，不是“本书分得对不对”。`code_status` 另行记录停用、交替、历史、专类优先等已知情况，其余为 `not_assessed`。`path_nodes` 与 `sources` 可以追到依赖版本、第五版官网覆盖数据、规则ID、表号和第五版PDF页码。

原始 `code` 不变；`matched_code + unparsed` 应等于 `normalized_code`。结果对象不在调用之间共享，避免批量结果互相污染。

## 新增规则的流程

1. 在本机提取PDF文字用于索引，不把全文提交到项目。
2. 从 `inventory.json` 找候选，回看完整相关页、双栏位置、上级说明和援引页；范围和继承不能只靠OCR相邻文本判断。
3. 在 `review_map.json` 记录实际核对的候选ID、分栏判断和关联规则；同页其他线索不自动升级为已核对。
4. 在 `rules.json` 写唯一ID、作用域、排除条件、执行类型、表引用、PDF页码、审核状态、实施状态、边界和样例。
5. 补表项时保留第五版的历史名称；历史地区不等同于停用类号，不以现代常识改书上的号码。
6. 启用前加正例、边界和反例，验证其他大类不被规则误伤。只有 `reviewed` 且声明已实现/部分实现的规则才能运行；部分实现必须写出边界。
7. 重跑测试和文档生成，检查来源、已核对范围与代码行为一致。

```bash
python -m unittest discover -v
python scripts/build_clc_catalogue.py
python scripts/build_clc_catalogue.py --check
git diff --check
```

候选索引可在本机重新生成（输出到新路径，不覆盖人工核对记录）：

```bash
pdftotext -layout /本机/第五版.pdf /本机临时目录/book.txt
python scripts/index_clc_rules.py /本机临时目录/book.txt \
  --output /本机临时目录/inventory-new.json \
  --markdown /本机临时目录/inventory-new.md
```

索引默认只输出公开定位元数据，不输出OCR片段、PDF/文字指纹和源文件名。只有本机研究确需上下文时才使用`--include-private-locators`，并将结果放在已忽略的`private/`或项目外。已有私有索引可通过`--public-from-index`生成公开副本，无需重读PDF。公开副本采用字段白名单，避免未来增加的私有字段被顺带发布。

发布前必须检查实际暂存区，而非只检查`.gitignore`。不提交PDF、OCR片段、个人路径、查询缓存、上传文件、日志、`.env`、证书密钥和代理凭据；提交作者使用GitHub隐私邮箱。本机原始索引保留在`private/`，不随仓库上传。

暂存待发布文件后执行`python -m scripts.check_publication`。该只读检查覆盖暂存区的全部文件及公开Excel模板内部元数据，报告只显示位置与风险类型，不输出敏感值；它是发布检查的一部分，不能替代人工审查或保证检测所有秘密。

## 不变的查询机制

SQLite继续只缓存书目原始数据，路径在每次读取书目后本地解析。因此规则更新不必清空国图缓存。分类结果不完整或补充表缺失不触发国图重试、批量熔断或额外网络等待。

`tests.preview_clc` 是隔离的手动页面夹具，只有显式运行该模块才替换查询函数；生产入口仍为 `flask --app app run`。夹具不向国图发请求，也不改书目缓存。`tests/fixtures/clc_preview.txt` 可用于三条批量页面验收。
